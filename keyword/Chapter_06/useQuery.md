# `gcTime`은 무엇인가요? 🍠
    
    **네트워크 요청 기준**
    
    `gcTime`은 **사용하지 않는 캐시 데이터를 얼마나 오래 메모리에 남겨둘지 정하는 시간**
    
    어떤 쿼리를 쓰던 컴포넌트가 사라지면 그 데이터는 “비활성 상태”가 되는데,
    
    이 상태에서 `gcTime`이 지나면 캐시에서 완전히 삭제됨
    
    즉,
    
    **“안 쓰는 데이터 언제 버릴지” 정하는 시간**
    
# `staleTime`은 무엇인가요? 🍠
    
    **메모리 관리 기준**
    
    `staleTime`은 **데이터를 fresh(신선한 상태)로 간주하는 시간**
    
    이 시간 동안은 같은 쿼리를 다시 써도 서버 요청 안 보내고 캐시 그대로 씀
    
    `staleTime` 지나면 stale 상태가 돼서 refetch 발생할 수 있음
    
    즉,
    
    **“이 데이터 다시 안 불러와도 되는 시간”**
    
# 두 값을 어떤 식으로 설정하여야 `캐싱 전략에 유리`한가요? 🍠
    
    **gcTime > staleTime 이렇게 두는 게 기본 전략**
    
    이유
    
    - `staleTime` 동안은 요청 안 보내서 성능 좋음
    - 그 이후에도 `gcTime` 동안은 캐시 남아 있어서 빠르게 UI 보여줄 수 있음
    
    예시
    
    ```
    staleTime:5분
    gcTime:30분
    ```
    
    이렇게 하면
    
    - 5분 동안은 서버 요청 없이 캐시 재사용
    - 30분 동안은 데이터 메모리에 살아 있어서 빠른 화면 전환 가능
    
    정리하면
    
    - 데이터 거의 안 바뀜 → `staleTime` 길게
    - 다시 방문 가능성 높음 → `gcTime` 길게
    - 실시간성 중요 → `staleTime` 짧게
    
    한 줄 요약하면
    
    **staleTime은 “언제 다시 요청할지”, gcTime은 “언제 캐시 버릴지” 기준**
